# ADR-001 — Adopt Architecture Decision Records

Status: Accepted
Related Ticket: ERP-003

## Context

Architecture and technology decisions were being made informally, with no durable record of *why* a particular option was chosen over the alternatives. `docs/architecture.md` captures the *what* — the current stack and principles — but not the reasoning trail as the project evolves and earlier choices get revisited or replaced.

## Decision

Adopt lightweight Architecture Decision Records in `.ai/adr/`, one file per decision, using the template at `.ai/templates/adr.md`. An ADR is written only after a real decision has been made with alternatives consciously evaluated — not backfilled for choices that were simply stated in earlier planning documents without a documented trade-off analysis.

## Alternatives Considered

- **No formal record-keeping, rely on git history/commit messages** — rejected because commit messages describe *what* changed, not the alternatives that were weighed or why the chosen option won.
- **A single running "decisions log" document instead of one-file-per-decision** — rejected because a growing single file becomes hard to reference, diff, and supersede individually; one file per decision keeps each entry addressable and independently supersedable.

## Consequences

Every non-trivial architecture decision going forward adds a small amount of documentation overhead. In exchange, decisions become traceable back to the ticket that prompted them via the `Related Ticket` field, and future decisions that reverse an earlier one can mark it `Superseded` rather than leaving contradictory reasoning scattered across the repo.
