# ADR-004 — Automated Secrets Scanning

Status: Accepted
Related Ticket: ERP-010

## Context

`CLAUDE.md` already stated "never commit secrets to Git" as a policy, but nothing enforced it — a manual PII/secrets check was run once before a `develop` -> `main` merge, but that doesn't scale and relies on remembering to do it. The project needed an automated guardrail that blocks a secret before it's committed, with a CI backstop in case the local hook is bypassed or never installed.

## Decision

Adopt **Gitleaks** (MIT license) as the secrets scanner, run via the `pre-commit` framework: a local git hook blocks commits containing secret-shaped strings (`.pre-commit-config.yaml`), and CI runs the identical check (`uv run pre-commit run gitleaks --all-files`) as a backstop against bypassed or missing local hooks.

The official `gitleaks/gitleaks-action` GitHub Marketplace Action is deliberately **not** used — it requires a paid license for repositories under an organization account (free tier is personal-account/single-repo only). Running the open-source Gitleaks binary directly through the `pre-commit` framework, both locally and in CI, achieves the same detection with zero licensing ambiguity, consistent with the project's open-source/free-only constraint (`docs/architecture.md`).

## Alternatives Considered

- **TruffleHog** — rejected as the primary tool: its standout feature (verifying whether a detected credential is still live against the actual provider) is unnecessary overhead for this project's scale, and its provider-verification calls add latency Gitleaks' pure pattern-matching doesn't have.
- **`gitleaks/gitleaks-action` (Marketplace Action)** — rejected due to the organization-account licensing requirement described above; the raw binary via `pre-commit` gives identical detection for free.
- **CI-only scanning, no local hook** — rejected: catching a secret only after it's pushed means it's already in remote history (and potentially already exposed via a fork, notification email, etc.); blocking at commit time is strictly better when cheap to do, which it is here.

## Consequences

Every commit now runs a sub-second local scan; CI re-runs the identical check. A new clone of the repo must run `uv run pre-commit install` once before the local hook is active — this is documented in `CLAUDE.md` and is a real (if small) new-contributor setup step. Ruff/mypy hooks planned for ERP-007 will be added to the same `.pre-commit-config.yaml` rather than a separate file.
