# ERP-013 — Redis Embedding Cache

Status: Done
Depends On: ERP-011

## Description

Adds the cache-aside Redis layer named in ADR-003 in front of the Ollama embedding calls in `app/embedding/`. Re-embedding identical text — re-ingesting the same document, or repeated retrieval queries — hits Redis instead of calling Ollama again. Cache key is a stable hash of the input text plus the configured model name (the embedding model is configurable, so the same text under a different model must not collide). Cache-aside: miss → call Ollama → store result → return; a Redis outage degrades to always-miss (falls through to Ollama), never a hard failure, matching ADR-003's "never load-bearing" decision. Deferred out of ERP-011's scope; see that ticket's Notes and `docs/superpowers/specs/2026-08-02-embedding-persistence-design.md`'s "Out of scope" line.

The caching is wired inside `OllamaEmbeddingClient` itself rather than at each call site, so both existing callers — `app/embedding/service.py`'s `embed_and_persist` (via `app/ingestion/jobs.py`) and `app/retrieval/service.py`'s `search` — get caching for free with no changes to either module.

## Acceptance Criteria

- [x] New dependency added: `redis` (official Python client)
- [x] `EmbeddingSettings` (`app/embedding/config.py`) gains `redis_url` and `cache_ttl_seconds`, following the existing `EMBEDDING_`-prefixed env var pattern
- [x] `app/embedding/cache.py`: `EmbeddingCache` protocol + `RedisEmbeddingCache` implementation — `get(model, text)` / `set(model, text, vector)`, keyed by a sha256 hash of `model:text`, TTL-bounded, and resilient to Redis being unreachable (logs and falls through rather than raising)
- [x] `OllamaEmbeddingClient` (`app/embedding/client.py`) wraps its Ollama calls with cache-aside lookups via an injectable `cache` parameter, defaulting to `RedisEmbeddingCache`; batches only the cache-miss subset of texts to Ollama and preserves input order in the returned vectors
- [x] No visible interface change to `app/ingestion/jobs.py` or `app/retrieval/service.py` — both already construct `OllamaEmbeddingClient(settings)` and get caching transparently
- [x] `docker-compose.yml` gets a local-dev `redis` service; CI runs the embedding-cache tests against a real Redis service container (no mocking the datastore itself, mirroring ERP-011's Postgres precedent)
- [x] All new modules covered by tests meeting the existing 90% coverage gate; `RedisEmbeddingCache` tests run against a real Redis, `OllamaEmbeddingClient` tests use an injected fake cache to stay isolated/fast (mirroring how those tests already fake Ollama)

## Notes

Redis is scoped to the embedding cache only in this ticket. ADR-003 also names a retrieval/query-result cache and a session/auth-token cache as future cache-aside uses of the same Redis instance — those are separate follow-ups, not covered here.
