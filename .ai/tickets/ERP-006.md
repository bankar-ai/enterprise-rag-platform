# ERP-006 — GitHub Repository Setup

Status: Done
Depends On: None

## Description

The repository had no `.github/` setup before real feature development starts: no `main` branch on the remote (only `develop`), no CI, and no PR template. This ticket pushes `main`, adds a minimal CI skeleton workflow, and adds a PR template requiring a linked ticket. The branch model and CI-scope decision are recorded in ADR-002.

`gh` CLI was not installed on the development machine and was installed via `winget install --id GitHub.cli` as part of this work.

## Acceptance Criteria

- [x] `main` branch created from `develop`'s tip and pushed to `origin`
- [x] `.github/workflows/ci.yml` added: checkout, `uv sync`, `pytest` on push/PR to `main`/`develop`
- [x] `.github/PULL_REQUEST_TEMPLATE.md` added with a required linked-ticket field
- [ ] `main` set as the GitHub default branch (via `gh repo edit --default-branch main`) — blocked on `gh auth login`, which requires interactive input the user must complete themselves
- [ ] Branch protection rules on `main` (require PR, no force-push/deletion) — same blocker as above; also worth revisiting once ERP-007 lands real CI checks that can be required

## Notes

See ADR-002 for the branch-strategy and CI-scope reasoning. The two unchecked items are follow-up for the user to complete once they run `gh auth login`.
