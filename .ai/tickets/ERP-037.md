# ERP-037 — Verify and Execute Chosen Deployment Infrastructure

Status: Backlog
Depends On: ERP-034, ERP-035

## Description

`D:\github-projects\infrastructure-options.md` (see ADR-008) records the researched hosting/infra
options for making this RAG platform reachable for a bounded 2-3 month test window (5-20 users max).
The current leading choice is GCP's Always Free `e2-micro` VM (permanently free, no expiration) for
app + FAISS-index hosting, with Render Starter (~$7/mo) as a paid fallback if `e2-micro`'s modest
specs (shared vCPU, ~1GB RAM) can't reliably run FastAPI + FAISS. Neon (Postgres), Upstash (Redis),
and Modal (serverless GPU for Ollama generation/embedding) are already decided with higher
confidence. This ticket is the actual verification-and-execution pass, not just the research.

## Acceptance Criteria

- [ ] Live-test the app (FastAPI + FAISS index files, no bundled Postgres/Redis) actually running on
      a GCP `e2-micro` instance under light concurrent load representative of 5-20 sporadic users;
      fall back to Render Starter if it doesn't hold up
- [ ] ERP-034 (default generation model tag fix) and ERP-035 (hardware sizing doc) are resolved
      before this ticket deploys anything live, so the deployed instance doesn't hit the same
      model-not-found or OOM failures found during local verification
- [ ] Real secrets generated fresh for the deployed instance (`AUTH_JWT_SECRET_KEY`, OIDC client
      secret if enabled, DB credentials) — never the local dev values
- [ ] Reverse proxy + TLS in front of the deployed FastAPI app
- [ ] `docker-compose.yml` (or equivalent) services set to restart automatically on failure/reboot
- [ ] Modal endpoint wired in for generation/embedding, confirmed reachable from the deployed app
- [ ] Neon and Upstash connection strings configured and confirmed reachable from the deployed
      instance's network/region
- [ ] Smoke-tested at ~10-20 simulated concurrent requests before calling this done
- [ ] Teardown steps documented (what to delete/cancel when the 2-3 month window ends) so walking
      away is a checklist, not a guess

## Notes

This ticket intentionally does not re-litigate the *choice* of provider — that's recorded in
ADR-008 and the shared infra doc. It only covers verifying the chosen option actually works and
executing the deployment. If live-testing reveals `e2-micro` doesn't hold up, update the shared doc's
status for that row (`Needs exploration` -> ruled out or reconsidered) rather than silently switching
without recording why.
