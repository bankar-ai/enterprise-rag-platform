# ERP-031 — Per-Tenant/Partitioned Vector Index

Status: Backlog
Depends On: ERP-026

## Description

Today's retrieval isolation (ERP-026) is oversample-then-filter: FAISS search runs owner-blind over one shared index, then results are filtered down to the caller's own documents before ranking. This works at small scale but degrades recall as tenants/data grow — a caller's own matches can be pushed out of the oversampled candidate window by other tenants' vectors, with no way to guarantee correctness short of oversampling arbitrarily far. Named as a deferred follow-up in ERP-026 and `docs/roadmap.md`'s "Multi-document Retrieval" item.

This ticket replaces that with real partitioning so retrieval correctness doesn't depend on tuning an oversample multiplier against unknown future scale.

## Acceptance Criteria

- [ ] Vector index is partitioned per tenant/owner (e.g. one FAISS index per `owner_id`, or an index structure with native per-tenant filtering) instead of a single shared index with post-hoc filtering
- [ ] `app/retrieval/service.py`'s owner-scoping no longer depends on an oversample multiplier to preserve recall
- [ ] Existing hybrid (BM25 + vector) fusion, reranking, and section-expansion behavior (ERP-014/015/016) is unchanged from the caller's perspective
- [ ] Migration path for existing single-index data (ERP-011 through ERP-025's persisted FAISS index) to the new partitioned layout
- [ ] Retrieval-quality evaluation (ERP-029) re-run to confirm no regression in Precision@k/Recall@k/MRR
- [ ] `ruff`, `mypy --strict`, and `pytest-cov --cov-fail-under=90` all pass

## Notes

Should be scoped with a design/brainstorming pass first — partitioning strategy (per-tenant index files vs. a single index with a native filtered-search capability) has real trade-offs on index-build cost, memory footprint, and cross-tenant admin queries (see ERP-032's related "admin cross-user visibility" gap, still out of scope here). Research current FAISS/vector-store options for native per-tenant filtering before committing to full physical partitioning (per CLAUDE.md's "Research Before Recommending" rule).
