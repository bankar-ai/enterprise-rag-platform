# ERP-031 — Per-Tenant FAISS Index Partitioning

Status: Done
Depends On: ERP-026

## Description

Replaces the single shared FAISS index (ERP-011 onward) with one physically separate FAISS index
per owner, closing a correctness-fragility gap in ERP-026's per-user data isolation: the previous
design oversampled a shared index's candidates and filtered them to the caller's own documents
after the fact, so a caller's true top-k vector matches could still be pushed out of the oversampled
window by other tenants' vectors, with no real bound other than a larger oversample multiplier.
After this ticket, isolation is structural -- a caller's search physically cannot return another
owner's vectors, because another owner's vectors are never in the index file being searched.

## Acceptance Criteria

- [x] One FAISS index per `owner_id`, persisted as separate index files keyed by owner id
      (`app/embedding/index.py`'s `OwnerFaissIndexStore`), lazily created on first ingestion for an
      owner and lazily loaded on first search
- [x] `embed_and_persist` writes new vectors into the correct owner's index
- [x] `app/retrieval/service.py`'s `search()` searches only the caller's own index; the old
      oversample-then-filter isolation mechanism (`filter_vector_ids_by_owner`) is removed --
      oversampling is kept only for RRF fusion quality
- [x] Hybrid fusion (RRF), reranking (ERP-015), and section-expansion (ERP-016) behavior unchanged
      from the caller's perspective (same request/response contract)
- [x] Migration path for existing single-index data: `app/embedding/migrate_to_per_owner.py`
      (`uv run python -m app.embedding.migrate_to_per_owner`), documented as a one-off script (not
      an Alembic migration, since it redistributes FAISS *data* files, not Postgres schema)
- [x] Design supports future sharding without a rewrite: every operation is keyed by `owner_id`
      rather than assuming one shared filesystem
- [x] `ruff`, `mypy --strict`, and `pytest-cov --cov-fail-under=90` all pass

## Notes

Design spec: `docs/superpowers/specs/2026-09-06-per-tenant-faiss-index-design.md`.

**Verification**: `uv run ruff check .` and `uv run mypy --strict app` both clean. Full suite run
against an isolated Postgres/Redis (this sandbox's default `localhost:5432`/`6379` were occupied by
another concurrent agent's containers, which was corrupting results with unrelated cross-session data
races -- reran against dedicated containers on ports 5433/6380 instead): `uv run pytest -q
--cov=app --cov-fail-under=90` -> **307 passed, 96% coverage** (2 pre-existing, unrelated
`tests/ingestion/test_parsers.py` docling-fallback tests deselected from that run due to a
Windows-native `access violation` crash under this sandbox's memory pressure from concurrent
agents; both pass individually in isolation, `6 passed` -- a known environment flake, not a
regression, matching the same failure mode noted in ERP-030's session log).

Two real bugs were caught and fixed during this verification pass, not just environment noise:
1. `FaissIndex.reconstruct` initially failed with `RuntimeError: reconstruct not implemented for
   this type of index` -- `IndexIDMap` (the type this repo always used) cannot translate an
   external id back to a reconstructable position. Fixed by switching the underlying index type to
   `IndexIDMap2`, which maintains that mapping explicitly.
2. `migrate()` originally crashed with `key not found` if a chunk row in Postgres had no matching
   vector in the legacy index -- always true for the *other* tests' unrelated data sharing the same
   test database. Fixed by skipping such a row with a logged warning instead of aborting the whole
   migration (also the more production-correct behavior, given ERP-011's already-documented
   non-atomic Postgres/FAISS writes).

Live-Ollama verification (ERP-029's evaluation harness, `uv run python -m app.evaluation.run`) was
not possible in this sandboxed environment -- no local Ollama instance was reachable. Verification
instead relied on the test suite above, including a new structural-isolation test
(`test_owner_store_owners_never_see_each_others_vectors` in `tests/embedding/test_index.py`) and a
router-level end-to-end isolation test
(`tests/retrieval/test_router.py::test_query_does_not_return_another_users_document`, carried over
from ERP-026 and still passing against the new architecture). Re-running the evaluation harness
against live Ollama to confirm no Precision@k/Recall@k/MRR regression is a deferred follow-up for
whoever next has Ollama available locally.

`EmbeddingSettings.faiss_index_path` was renamed to `faiss_index_dir` (env var
`EMBEDDING_FAISS_INDEX_DIR`) -- a breaking config change for any existing deployment, which is why
the migration script exists.
