# ERP-030 — Evaluation (Generation Quality)

Status: Done
Depends On: ERP-029

## Description

Second half of the "Evaluation" project goal, following ERP-029's retrieval-quality harness. Scores the LLM's generated answers using the RAG triad (Faithfulness, Answer Relevancy, Context Precision) via Ragas, with a hand-rolled fallback judge for when Ragas's documented local-Ollama reliability issues bite. Reuses ERP-029's golden dataset unchanged.

## Acceptance Criteria

- [x] `app/evaluation/judges.py`: `GenerationJudge` interface with `RagasJudge` (default, uses Ragas's `Faithfulness`/`ResponseRelevancy`/`LLMContextPrecisionWithoutReference` against a local-Ollama-backed judge LLM) and `OllamaLLMClientJudge` (selectable fallback, hand-rolled scoring prompts against the existing `OllamaLLMClient`)
- [x] `app/evaluation/generation_runner.py`'s `run_generation_evaluation()` runs each golden query through the real pipeline building blocks (`search()` → `build_prompt()` → `llm_client.generate()`) to get an answer and its actual context chunks, scores with the selected judge, persists to a new `generation_evaluation_runs` table
- [x] Same never-load-bearing lifecycle as ERP-029: dedicated temp FAISS index, all transient eval data (user, documents, chunks) deleted after each run, only the summary row persists
- [x] `uv run python -m app.evaluation.generation_run [--judge ragas|ollama]` CLI entrypoint
- [x] Not wired into CI as a gate; `tests/evaluation/` uses a fake `LLMClient` and mocked Ragas metrics — no real Ollama/Ragas dependency for CI
- [x] `ruff`, `mypy --strict`, and `pytest-cov --cov-fail-under=90` all pass (298 passed, 97.06% coverage)

## Notes

Design classified as Architectural (brainstorming skill). Design spec: `docs/superpowers/specs/2026-09-06-generation-evaluation-design.md`. Plan: `docs/superpowers/plans/2026-09-06-generation-evaluation.md`.

**Critical dependency-pinning detail — do not "clean up" without reading this first:** `ragas` is pinned to `==0.3.9` in `pyproject.toml`, and `[tool.uv] constraint-dependencies` includes `"langchain-community<0.4"`. Both `ragas==0.4.3` (latest at the time) and `ragas==0.3.9` unconditionally import a `langchain_community.chat_models.vertexai` submodule that was removed in `langchain-community>=0.4` — a confirmed upstream ragas bug (github.com/explodinggradients/ragas issues #2741, #2745, #2753), breaking `import ragas` entirely regardless of which LLM backend is actually used. Without both the version pin and the constraint, the app fails to import anything from `app.evaluation.judges`. Revisit this pin once ragas ships a fix.

**Confirmed in practice, not just in research:** `RagasJudge` run live against local Ollama (`qwen3:8b`) hung for 10+ minutes with zero output before being killed — the exact local-Ollama reliability issue the fallback judge was built for. `OllamaLLMClientJudge` completed the same golden dataset in seconds with plausible scores (Faithfulness=1.0, Answer Relevancy=0.75, Context Precision=0.575). `RagasJudge`'s wiring is otherwise verified correct via a mocked-metrics unit test — the failure mode is Ragas's own runtime behavior against Ollama, not a bug in this integration.

Deferred (see spec): reference-based metrics (Answer Correctness, Context Recall) if a ground-truth-answer dataset is ever authored; wiring either evaluation harness as a CI gate; eventual replacement/integration with the future LLMOps & Evaluation Platform.
