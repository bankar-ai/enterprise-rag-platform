# ERP-003 — ADR Framework

Status: Done
Depends On: ERP-002

## Description

Define the Architecture Decision Record format and lifecycle used in `.ai/adr/`, per the pointer left in `.ai/README.md` and `.ai/adr/README.md`. This includes the reusable template at `.ai/templates/adr.md`, the `Accepted / Superseded` status lifecycle, and a `Related Ticket` field linking each ADR back to the ticket that prompted it.

The first real ADR, `ADR-001: Adopt Architecture Decision Records`, was written as part of this ticket — the decision to adopt ADRs as a practice. No other ADRs were backfilled: per `.ai/adr/README.md`, ADRs are written only after a real decision has been made with alternatives consciously evaluated, and the existing tech stack choices in `docs/architecture.md` weren't recorded with that kind of trade-off analysis at the time.

## Acceptance Criteria

- [x] `.ai/templates/adr.md` created with Status, Related Ticket, Context, Decision, Alternatives Considered, and Consequences fields
- [x] Status lifecycle defined: Accepted / Superseded
- [x] `.ai/adr/ADR-001.md` written using the new template
- [x] `.ai/adr/README.md` and `.ai/templates/README.md` updated to reflect that the ADR template and ADR-001 now exist

## Notes

Session templates are out of scope here — built out by ERP-004.
