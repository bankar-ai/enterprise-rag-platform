# ERP-025 — Non-Locking Migration Strategy for `search_vector`

Status: Done
Depends On: ERP-024

## Description

ERP-014's migration (`a97a8780506f`) adds `chunks.search_vector` as a `GENERATED ALWAYS AS (...) STORED` column and builds its GIN index with a plain (non-`CONCURRENTLY`) `CREATE INDEX`. Both take an `ACCESS EXCLUSIVE` lock on `chunks` for the duration — harmless at today's near-zero row count, but a full-table rewrite + index build under an exclusive lock would block all reads and writes to `chunks` for as long as it takes once the table holds meaningful production data.

Convert to the standard non-locking pattern: a plain (non-generated) nullable column kept in sync by a trigger instead of `GENERATED ALWAYS`, existing rows backfilled in batches instead of one full-table rewrite, and the GIN index built `CONCURRENTLY` outside the migration's transaction.

## Acceptance Criteria

- [x] New Alembic migration (chained after the current head) converts `chunks.search_vector` from a generated column to a plain nullable `TSVECTOR` column kept in sync by a `BEFORE INSERT OR UPDATE OF text` trigger (`to_tsvector('english', text)`)
- [x] Existing index is dropped and rebuilt as `CREATE INDEX CONCURRENTLY` (via Alembic's `autocommit_block()`, since `CONCURRENTLY` cannot run inside a transaction)
- [x] Any rows lacking `search_vector` are backfilled in batches (`WHERE search_vector IS NULL LIMIT n`, looped), not one full-table `UPDATE`
- [x] `app/ingestion/models.py`'s `ChunkRecord.search_vector` no longer uses `Computed(...)`; the trigger function/trigger are created via SQLAlchemy DDL `event.listen(..., "after_create", ...)` on `ChunkRecord.__table__`, so `Base.metadata.create_all` (used by the test suite) reproduces the same auto-populate behavior the migration gives production
- [x] Downgrade path reverses cleanly: drop trigger/function, drop the plain index, restore the `GENERATED ALWAYS` column + non-concurrent index (matching ERP-014's original migration)
- [x] Existing full-text-search behavior (`search_chunks_by_text`, `tests/ingestion/test_repository.py`, and `/retrieval/query` hybrid-search tests) passes unmodified — this is an internals-only change, no behavior or contract change
- [x] `uv run alembic upgrade head` and `uv run alembic downgrade -1` both verified to run cleanly

## Notes

Depends on ERP-024 (GIN index declared on the model) landing first, so this ticket's model changes build on a model that already declares the index — avoids the two tickets fighting over the same `__table_args__` edit.
