# ERP-017 — Generation (RAG Answer Synthesis)

Status: Done
Depends On: ERP-014, ERP-015, ERP-016

## Description

Adds the "generation" half of Retrieval-Augmented Generation: a new `POST /generation/query` endpoint that runs the existing hybrid retrieval pipeline unmodified, then synthesizes a single grounded answer with inline numbered citations (`[1]`, `[2]`, ...) via a local Ollama-hosted LLM (Qwen3). Until now, `POST /retrieval/query` (ERP-012 through ERP-016) returned only ranked, provenance-tagged chunks — callers had to read the passages themselves. See `docs/superpowers/specs/2026-08-31-generation-design.md` for the full design and `docs/superpowers/plans/2026-08-31-generation.md` for the implementation plan.

## Acceptance Criteria

- [x] New `app/generation/` module (`config.py`, `client.py`, `prompt.py`, `schemas.py`, `service.py`, `router.py`), mirroring `app/retrieval/`'s and `app/embedding/`'s existing shape
- [x] `GenerationSettings` (`GENERATION_` env prefix) with `ollama_host`, `model = "qwen3"`, `max_context_chars = 8000`, `temperature = 0.1`
- [x] `LLMClient` `Protocol` + `OllamaLLMClient`, injectable for testing, same pattern as `EmbeddingClient`/`OllamaEmbeddingClient`
- [x] `build_prompt` numbers retrieved chunks `[1]..[n]` in ranked order and truncates to `max_context_chars`, dropping the lowest-ranked tail (never an arbitrary cut) rather than partially including a chunk
- [x] `GenerationQuery` mirrors `RetrievalQuery` (`query`, `top_k`, `rerank`, `expand_sections`); `GenerationResponse` returns `answer: str` plus a `citations: list[Citation]` for provenance
- [x] `service.generate` calls `app.retrieval.service.search` unmodified with the same params (hybrid fusion, optional rerank, optional section expansion all unchanged); an empty retrieval result short-circuits to a fixed "not enough information" response without constructing an `LLMClient` or calling the LLM
- [x] `POST /generation/query` follows `app/retrieval/router.py`'s try/except → `HTTPException(503)` pattern; registered in `app/main.py` alongside `retrieval`
- [x] No new dependency — `ollama` (already used by `app/embedding/client.py`) covers chat completion as well as embeddings
- [x] All new modules covered by tests meeting the 90% coverage gate

## Notes

Sync-only response for this ticket — no streaming (SSE/chunked), no multi-turn conversation memory; both deferred to `docs/roadmap.md` as later work. Standalone endpoint by design, not merged into `/retrieval/query`, so retrieval's existing contract stays untouched. See `.ai/sessions/2026-08-31-generation.md` for the brainstormed design decisions and full commit list.
