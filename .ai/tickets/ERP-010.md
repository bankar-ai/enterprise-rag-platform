# ERP-010 — Automated Secrets Scanning Guardrail

Status: Done
Depends On: None

## Description

Adds an automated secrets-scanning guardrail (Gitleaks, via `pre-commit`) so `CLAUDE.md`'s "never commit secrets to Git" rule is enforced by tooling, not just policy — prompted by a manual PII/secrets check run before the first `develop` -> `main` merge, which highlighted that nothing currently prevented a secret from being committed. See ADR-004 for the tool-choice reasoning, including why the licensed `gitleaks-action` was avoided.

## Acceptance Criteria

- [x] `pre-commit` added as a dev dependency via `uv add --dev pre-commit`
- [x] `.pre-commit-config.yaml` created with the Gitleaks hook
- [x] Local hook installed and verified to actually block a staged fake secret (confirmed with a fake GitHub token; a well-known AWS example key was correctly allowlisted, ruled out as a false negative)
- [x] CI runs the same check (`.github/workflows/ci.yml`) as a backstop
- [x] `CLAUDE.md` documents the guardrail and the one-time `uv run pre-commit install` setup step
- [x] ADR-004 records the tool-choice decision
