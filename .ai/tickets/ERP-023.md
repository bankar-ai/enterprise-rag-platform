# ERP-023 — Require CI Status Checks in `main`'s Branch Protection

Status: Done
Depends On: None

## Description

`main`'s branch protection does not currently require the CI workflow (`.github/workflows/ci.yml`, job `test`: gitleaks, ruff, mypy, `alembic upgrade head`, pytest+coverage against real Postgres/Redis service containers) to pass before a PR can merge. CI has been green and enforcing real signal since ERP-011 (Postgres) and ERP-013 (Redis); there's no remaining reason not to make it a required check.

## Acceptance Criteria

- [x] `main`'s branch protection requires the `test` status check to pass before merging
- [x] Existing requirements (PR review requirement, if any) are preserved, not replaced
- [x] Verified by inspecting the updated branch protection settings via the GitHub API

## Notes

Purely a GitHub repository setting change (via `gh api`), not an application code change.

Claude's own `gh api -X PUT .../branches/main/protection` call was denied by this environment's auto-mode permission classifier on three separate attempts (see the 2026-09-05 session log). The user ran the command directly instead, from their own terminal, and it succeeded on the second try (the first hit a 422 from GitHub's schema validation over the `restrictions` field's null encoding, not a permissions issue). Final applied settings: `required_status_checks: {strict: true, contexts: ["test"]}`, with `enforce_admins`, `required_pull_request_reviews`, `allow_force_pushes`, and `allow_deletions` all preserved at their prior (pre-existing) values.
