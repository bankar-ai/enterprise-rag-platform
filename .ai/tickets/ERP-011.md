# ERP-011 — Embedding Generation & Persistence

Status: Done
Depends On: ERP-009

## Description

Turns chunked-but-ephemeral ingestion output into embedded, durably-persisted chunks: Postgres for chunk text/metadata, FAISS (local disk) for vectors, Nomic Embed via Ollama for embeddings — wired into the existing async ingestion job pipeline. Per ADR-003. See `docs/superpowers/specs/2026-08-02-embedding-persistence-design.md` for the design and `docs/superpowers/plans/2026-08-06-embedding-persistence.md` for the implementation plan.

## Acceptance Criteria

- [x] New dependencies added: `sqlalchemy`, `alembic`, `psycopg[binary]`, `ollama`, `faiss-cpu`
- [x] Postgres engine/session setup (`app/core/db.py`) and connection settings (`app/core/config.py`)
- [x] `documents`/`chunks` SQLAlchemy models and an Alembic migration creating them
- [x] `app/ingestion/repository.py` persists a document and its chunks in one transaction
- [x] `app/embedding/` module: Ollama-backed embedding client, FAISS index wrapper (load/add/save), and an `embed_and_persist` orchestration service
- [x] `run_ingestion_job` extended to embed + persist after chunking, with the same failure handling/logging as the existing parse/chunk stage
- [x] `docker-compose.yml` Postgres service for local dev; CI runs against a real Postgres service container
- [x] All new modules covered by tests meeting the existing 90% coverage gate; embedding tests mock Ollama, DB tests run against real Postgres

## Notes

Redis embedding cache (also named in ADR-003) is explicitly deferred to a follow-up ticket — it's cache-aside and non-load-bearing, so adding it later changes nothing about correctness.
