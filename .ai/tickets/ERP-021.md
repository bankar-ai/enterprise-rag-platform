# ERP-021 — Redis Retrieval/Query-Result Cache

Status: Backlog
Depends On: ERP-014, ERP-013

## Description

Adds the retrieval/query-result cache-aside layer named in ADR-003 in front of `app/retrieval/service.py`'s `search()`. A repeated query (same `query` text, `top_k`, `rerank`, and `expand_sections`) hits Redis instead of re-running the full hybrid pipeline (query embedding, FAISS search, Postgres BM25 search, RRF fusion, hydration, and optional cross-encoder rerank). Cache key is a hash of all four parameters that affect `search()`'s output. Cache-aside, short TTL (5 minutes default): miss → run pipeline → store result → return; a Redis outage degrades to always-miss, never a hard failure, matching ADR-003's "never load-bearing" decision.

The caching is wired inside `search()` itself rather than at each call site, so both existing callers — the `POST /retrieval/query` router and `app/generation/service.py`'s internal use of `search()` — get caching for free with no changes to either module. This is the second of ADR-003's three named Redis uses (after ERP-013's embedding cache); the third (session/auth-token cache) is out of scope here — see Notes.

Design: `docs/superpowers/specs/2026-09-04-retrieval-query-cache-design.md`.

## Acceptance Criteria

- [ ] `app/retrieval/config.py` gains `RetrievalSettings` (`RETRIEVAL_`-prefixed `redis_url`, `cache_ttl_seconds` defaulting to 300s), following the existing `RerankerSettings` pattern in that file
- [ ] `app/retrieval/cache.py`: `RetrievalCache` protocol + `RedisRetrievalCache` implementation — `get(cache_key)` / `set(cache_key, results)`, resilient to Redis being unreachable (logs and falls through rather than raising)
- [ ] `app/retrieval/service.py`'s `search()` checks the cache first (key hashing `query` + `top_k` + `rerank` + `expand_sections`), returns on hit, and caches the result on miss (including an empty-results miss); gains an injectable `cache` parameter defaulting to `RedisRetrievalCache`
- [ ] No visible interface change to `app/retrieval/router.py` or `app/generation/service.py` — both already call `search()` and get caching transparently
- [ ] No new infra: reuses the `redis` service already in `docker-compose.yml`/CI (ERP-013)
- [ ] All new/modified code covered by tests meeting the existing 90% coverage gate; `RedisRetrievalCache` tests run against a real Redis, `search()` tests use an injected fake cache to stay isolated/fast

## Notes

ADR-003 also names a session/auth-token cache as a third Redis use. Not covered here — no authentication system exists yet in this project to define what a session/auth token is. Blocked on a future Authentication ticket.
